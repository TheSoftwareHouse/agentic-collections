# Configuring Xcode for iOS

**Plugin:** [`tsh-stack-ios`](/docs/plugins/tsh-stack-ios/)  
**Invoke:** `/tsh-stack-ios:configuring-xcode-for-ios`, and Claude also loads it when the work matches its description  
**Used by:** [`implementing-ios`](/docs/plugins/tsh-stack-ios/skills/implementing-ios) sends a greenfield app here to set up the project before any app code

The recommended build setup for a native iOS app: which Xcode and Swift to use, how the project, targets and build configurations are laid out, the Swift language mode and concurrency settings, dependencies through Swift Package Manager, and the `xcodebuild` commands CI runs. It is about configuration only: how app code is written belongs to `implementing-ios`, what tests assert is out of scope, and release pipelines (TestFlight, App Store submission, certificate management at scale) are not covered. Nor is the `ios/` project that React Native or Flutter generates, whose Podfile and build settings that framework's tooling manages.

The defaults are for new projects, not a verdict on existing ones. Local conventions outrank the skill, a working project that differs is not a defect, and a project generated by XcodeGen or Tuist is edited through its manifest.

## Key areas

| Area | Coverage |
| :-- | :-- |
| **Versions** | Written against Xcode 27.2, Swift 6.4 and the iOS 27.2 SDK; reads what the repository pins before applying anything. App Store Connect has required Xcode 26 and an iOS 26 SDK for uploads since 28 April 2026, which governs the build SDK, not the deployment target |
| **Project and build settings** | Project layout, buildable folders, the JSON project format, `.xcconfig` configurations, schemes, signing basics, generated `Info.plist`, the privacy manifest and String Catalogs |
| **Swift language mode and concurrency** | Swift 6 mode, `MainActor` default isolation, the two Approachable Concurrency features, package settings, and a staged migration from Swift 5 mode |
| **Swift Package Manager** | Version requirements, a committed `Package.resolved`, local packages as modules, and leaving CocoaPods |
| **Formatting, linting and CI** | SwiftFormat pinned through a build-tools package, its configuration and commands, keeping an existing SwiftLint, `xcodebuild` build and test, warnings as errors switched on from CI through the project's own `.xcconfig` so remote packages are not affected, package caching |
| **Xcode version and upgrades** | Version policy, pinning, deployment-target guidance, what Xcode 27 changed, and the upgrade procedure |

## How it works

1. **Read the ground truth:** the selected Xcode, the team's pin, `SWIFT_VERSION`, the deployment target, the isolation settings, the dependency manager and what CI runs.
2. **Decide greenfield or brownfield:** a new project takes the defaults; an existing one gets the smallest staged change.
3. **Settle the open decisions:** with no deployment target, ask.
4. **Load the reference** for the change.
5. **Check the gate,** when the change touches build settings or CI: CI builds and tests on a pinned Xcode and fails on warnings.
6. **Apply the smallest change,** preferring an `.xcconfig` edit, and say when a change alters runtime behaviour.
7. **Verify** with a clean build and the test suite using CI's own `xcodebuild` command, and launch the app in the Simulator after any change to the deployment target, isolation defaults or linked packages.

## Non-negotiable rules

| Severity | Rule |
| :-- | :-- |
| MUST | In an existing project, make the smallest staged change and record the remaining gap |
| MUST | Ask for the deployment target when the project has none or the user has not stated one |
| MUST | New targets and packages use Swift 6 language mode; an existing Swift 5-mode codebase migrates module by module |
| MUST | Add dependencies through Swift Package Manager and commit `Package.resolved`; no new CocoaPods or Carthage dependency, since CocoaPods trunk goes read-only on 2 December 2026 |
| MUST | Keep build settings in committed `.xcconfig` files, one per configuration |
| NEVER | Commit a secret in an `.xcconfig`, `Info.plist`, scheme or source file |
| MUST | Ship a `PrivacyInfo.xcprivacy` in every app target that uses a required-reason API |
| MUST | CI builds and tests with `xcodebuild` on a pinned Xcode, using the committed `Package.resolved`, and fails on compiler warnings |
| MUST | Run one formatter (SwiftFormat in a new project), configured by a committed file, in CI |
