# Configuration and Environments

Use this reference when choosing a config format, adding parameters, env vars or secrets, changing the kernel, or building a reusable bundle in a Symfony 5.4..8.x project.

## Where a Value Belongs

| Value | Mechanism | Why |
| --- | --- | --- |
| Rarely changes (e.g. `NUMBER_OF_ITEMS = 10`) | PHP class constant | Usable everywhere, including Twig templates and Doctrine entities |
| Application behaviour (email sender, feature toggles) | `app.`-prefixed parameter in `config/services.yaml` | Does not change per machine |
| Infrastructure that changes per machine (database credentials) | env var | Does not modify application behaviour |
| Sensitive value (API key, database password) | secrets vault | Stored encrypted |

- **Do not**: define application-behaviour options as env vars.
- **Do not**: use the Config component for application options unless "the application configuration is reused multiple times and needs rigid validation".
- **Cons of constants**: it is complicated to redefine their values in tests; parameters are only available where the service container is.

## Config Formats

There is no practical or performance difference between formats: Symfony transforms all of them into PHP and caches them.

- **YAML**: the default; concise and readable, but not all IDEs autocomplete or validate it.
- **PHP**: dynamic configuration with arrays; in 7.4 it gets autocompletion and static analysis through array shapes and the autogenerated `config/reference.php`.
- **XML**: deprecated in 7.4, no longer supported in 8.0. It offers no capabilities beyond the other formats.
- **Config builders** (5.3+): generated classes under the `Symfony\Config` namespace; only root classes are ConfigBuilders. Deprecated in 7.4 ("return PHP arrays from your config instead"); fluent methods removed in 8.0.
- **Pitfalls**:
  - 5.4 loads only YAML by default; XML or PHP config needs a change in `src/Kernel.php`.
  - Do not exclude `var/cache/dev/Symfony/Config/` from the IDE if you rely on config builder autocompletion.
  - Using `$this` or the loader's internal scope in PHP config files is deprecated in 7.4 (and throws, marked as a BC break) and removed in 8.0; use the `$loader` variable, which exposes only the public API.

7.4+ array form:

```php
return App::config([
    'framework' => [
        'secret' => env('APP_SECRET'),
        'esi' => true,
        'session' => [
            'handler_id' => null,
            'cookie_secure' => 'auto',
            'cookie_samesite' => 'lax',
        ],
    ],
]);
```

Run `php bin/console config:dump-reference` to see all options of a bundle.

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| YAML default; XML, PHP; config builders (5.3) | same | 7.4: XML and config builders deprecated; array shapes, `AppReference`, `config/reference.php` | XML and fluent builders removed |

## Imports

- **Use**: `imports` with `resource`, globs allowed (`/etc/myapp/*.yaml`). `ignore_errors: not_found` discards only a missing file; `ignore_errors: true` discards all errors, including invalid code. In PHP the third argument of `import()` is `ignore_errors`.
- **Pitfall**: parameters cannot build import paths; `resource: '%kernel.project_dir%/somefile.yaml'` does not work.

## Parameters

Key-value pairs in the container, defined under `parameters` in `config/services.yaml` and overridable per environment (`config/services_dev.yaml`, `config/services_prod.yaml`).

- **Use**: the `app.` prefix and one or two words: `app.contents_dir`, not `app.dir`.
- **Types**: strings, booleans, arrays, binary (`!!binary`), constants (`!php/const App\Entity\BlogPost::MAX_ITEMS`), enum cases (`!php/enum App\Enum\PostState::Published`, shown in the 7.4 docs).
- **Access**: `#[Autowire(param: 'app.contents_dir')]` (the recommended way), `getParameter()` in `AbstractController`, `services._defaults.bind`, or `ContainerBagInterface` for many parameters. Autowiring does not work for parameters, so inject them explicitly.
- **Pitfalls**:
  - Escape a literal `%` by doubling it: `'https://symfony.com/?foo=%%s&bar=%%d'`.
  - Names starting with `.` (e.g. `.mailer.transport`) exist only during container compilation.
  - Parameters can only be set before compilation.
  - In XML, values between `<parameter>` tags are not trimmed.

```php
use Symfony\Component\DependencyInjection\Attribute\Autowire;

class MessageGenerator
{
    public function __construct(
        #[Autowire(param: 'app.contents_dir')]
        private string $contentsDir,
    ) {
    }
}
```

`parameterCannotBeEmpty()` (7.2) rejects `null`, `''` or `[]`; it is checked when the parameter is retrieved, not at compile time. Inspect with `php bin/console debug:container --parameters`.

## Environments

`APP_ENV` (in `.env` or `.env.local`, or per command: `APP_ENV=prod php bin/console command_name`) selects the environment; typical ones are `dev`, `prod` and `test`. Files load in this order, later wins:

1. `config/packages/*.<ext>`
2. `config/packages/<env>/*.<ext>`
3. `config/services.<ext>`
4. `config/services_<env>.<ext>`

`when@<env>` (5.3+) keeps per-environment config in the same file; YAML anchors can reuse a block (`when@test: *webpack_prod`).

```yaml
when@prod:
    webpack_encore:
        cache: true
```

- **New environment**: create `config/packages/<env-name>/` (e.g. `staging`), add only the differing files, select it with `APP_ENV`. Symbolic links between environment directories can reuse configuration.
- **`APP_RUNTIME_ENV`** (7.4 docs): names the deployment place (e.g. `staging`) independently of `APP_ENV`; stored in `kernel.runtime_environment`, falls back to `kernel.environment`. The same compiled container works everywhere you deploy it, and Symfony uses it to select the secrets vault.
- **Pitfalls**:
  - A `when@<env>` block in `services` does not inherit `_defaults`; redefine `_defaults` in every block that needs it.
  - The web profiler must never be enabled in production.

## Env Vars and `.env` Files

`%env(APP_SECRET)%` is resolved at runtime, once per request, so changing it needs no cache clear. Values are always strings; cast them with processors. Names are uppercase by convention.

- **Use**: infrastructure options that change between machines; one `.env` file per environment when needed.
- **Do not**: read `$_ENV` or `$_SERVER`; there is no need in Symfony applications.
- **Default**: an undefined env var throws; give a default with `env(SECRET): 'some_secret'` under `parameters`.

| File | Purpose | Committed |
| --- | --- | --- |
| `.env` | defaults good for local development, no production values | yes |
| `.env.local` | local overrides for all environments; ignored in `test` | no |
| `.env.<env>` | per-environment values | yes |
| `.env.<env>.local` | machine-specific per-environment values | no |

Priority from highest: real env vars, `.env.local.php`, `.env.<env>.local`, `.env.<env>`, `.env.local`, `.env`. Real env vars win because `variables_order` contains `E` (the PHP default); `.env` never overwrites an existing env var.

`.env` syntax: references `DB_PASS=${DB_USER}pass`, defaults `DB_PASS=${DB_USER:-root}pass`, commands `START_TIME=$(date)`.

- **Pitfalls**:
  - Order matters when one env var depends on another.
  - Command substitution `$(...)` does not work on Windows.
  - Double quotes interpolate but keep `#` literal; single quotes are literal.
  - Dumping `$_SERVER`, `$_ENV` or `phpinfo()` exposes credentials.
  - Some configuration features are not compatible with env vars (e.g. conditional parameters: the option always exists and is `null` when undefined).
  - `overrideExistingVars` (in `loadEnv()`, `bootEnv()`, `populate()`) overrides system env vars but not those from `.env` files.
- **Production**: create `.env.local` on the server, or run `composer dump-env prod` after each deploy; it dumps all `.env` files into `.env.local.php`, which Symfony loads instead of parsing `.env` files. Without Composer: `APP_ENV=prod APP_DEBUG=0 php bin/console dotenv:dump` (Flex 1.2+, after registering `Symfony\Component\Dotenv\Command\DotenvDumpCommand`).
- **Custom loaders**: implement `EnvVarLoaderInterface`; autoconfigured with the default `services.yaml`, otherwise tag `container.env_var_loader`.
- **Inject into a service**: `#[Autowire(env: ...)]` (6.3) or `_defaults.bind`.

```php
use Symfony\Component\DependencyInjection\Attribute\Autowire;

final class MailSettings
{
    public function __construct(
        #[Autowire(env: 'SOME_ENV_VAR')]
        private string $senderName,
        #[Autowire(env: 'bool:SOME_BOOL_ENV_VAR')]
        private bool $allowAttachments,
    ) {
    }
}
```

Inspect with `debug:dotenv` (5.4+) and `debug:container --env-vars`.

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| `debug:dotenv` | `#[Autowire(env:)]` (6.3) | `SYMFONY_DOTENV_PATH` or `extra.runtime.dotenv_path` (7.1); `#[Autowire(env:)]` casts to null or bool (7.1); `StaticEnvVarLoader` (7.1) | same |

## Env Var Processors

Syntax `%env(processor:VAR)%`; any number of processors can be combined.

| Processor | Result |
| --- | --- |
| `string`, `int`, `float`, `const`, `base64` | cast or decode |
| `bool` / `not` | `'true'`, `'on'`, `'yes'`, non-zero numbers and numeric strings other than `'0'`/`'0.0'` are true; `not` inverts |
| `json` | array or `null` |
| `resolve` | replaces `%parameter%` placeholders |
| `csv` | array; empty string gives empty array |
| `shuffle` | shuffled array |
| `file` / `require` | file contents / return value of a PHP file |
| `trim` | strips whitespace; useful with `file` |
| `key:NAME` | one key of an array |
| `default:fallback_param` | the parameter when the var is unavailable; `default::` gives `null` |
| `url` / `query_string` | parsed into an associative array |
| `enum:FooEnum` | `\BackedEnum`, fully qualified name |
| `defined` | `true` if defined and not `''` or `null` |
| `urlencode` | URL-encoded; for values that are not DSN-compatible |

```yaml
parameters:
    env(AUTH_FILE): '%kernel.project_dir%/config/auth.json'

google:
    auth: '%env(json:file:resolve:AUTH_FILE)%'
```

The steps in this example run right to left: `resolve`, then `file`, then `json`. In PHP: `env('AUTH_FILE')->resolve()->file()->json()`.

- **Pitfall**: with `url`, the leading `/` is trimmed from the `path` component.
- **Pitfall**: resolving env vars at compile time (`resolveEnvPlaceholders(..., true)`) is discouraged; the cache must be cleared manually when the env var changes.
- **Custom processor**: implement `EnvVarProcessorInterface` (`getEnv(string $prefix, string $name, \Closure $getEnv)` and static `getProvidedTypes()`); tagged `container.env_var_processor` automatically with default autoconfiguration.

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| core processors | `enum`, `shuffle` (6.2); `defined`, `urlencode` (6.4 in the DI changelog; the 7.4 docs say 7.1) | same | same |

## Secrets Vault

Sensitive values encrypted with asymmetric keys, one key pair per environment, in `config/secrets/<env>/`, referenced like env vars: `password: '%env(DATABASE_PASSWORD)%'`. Enabled by default; requires the sodium extension.

- **Use**: sensitive configuration such as API keys and database passwords.
- **Do not**: create a `test` vault; put test values in `.env.test` (`DATABASE_PASSWORD="testing"`).

```bash
php bin/console secrets:set DATABASE_PASSWORD
APP_RUNTIME_ENV=prod php bin/console secrets:generate-keys
APP_RUNTIME_ENV=prod php bin/console secrets:set DATABASE_PASSWORD
echo -n "$DB_PASS" | php bin/console secrets:set DATABASE_PASSWORD -
php bin/console secrets:set REMEMBER_ME --random
APP_RUNTIME_ENV=prod php bin/console secrets:decrypt-to-local --force
```

Other commands: `secrets:list [--reveal]`, `secrets:remove`, `secrets:encrypt-from-local`, `secrets:set NAME --local` (writes a plain env var to `.env.<env>.local`). There is no rename command: create a new secret and remove the old one.

- **Files**: `dev.encrypt.public.php` can be safely committed; `dev.decrypt.private.php` can be committed if the dev vault holds no highly sensitive secrets; `prod.decrypt.private.php` must never be committed. Developers and CI services do not need it.
- **Key delivery**: upload `prod.decrypt.private.php` to the server, or set `SYMFONY_DECRYPTION_SECRET` to `php -r 'echo base64_encode(require "config/secrets/prod/prod.decrypt.private.php");'`. After `secrets:decrypt-to-local --force` (writes `.env.prod.local`) the key need not stay on the server.
- **Pitfalls**:
  - Environment variables override secrets; do not define both with the same name by accident.
  - If the prod decryption key is exposed, run `secrets:generate-keys --rotate` (needs the current decryption key).
  - Container compilation and cache warmup do not need the decryption key; values resolve at runtime.

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| `secrets:*` commands (since 4.4) | same | `secrets:reveal` (7.1); `kernel.secret` derived from `SYMFONY_DECRYPTION_SECRET` when `APP_SECRET` is undefined (7.2) | same |

## Kernel

`src/Kernel.php` extends `Kernel` and uses `MicroKernelTrait`. It sets up bundles, creates the container and serves requests through `handle()`. `registerBundles()`, `configureRoutes()` and `configureContainer()` must all be implemented; the default `configureContainer()` loads `config/packages/*` then `config/packages/<env>/`.

- **Use**: the default kernel; you usually don't need your own front controller or kernel class.
- **Use**: `build()` to register compiler passes with `addCompilerPass()`; the kernel can also implement `CompilerPassInterface` itself.
- **Alternative kernels**: possible (e.g. `AdminKernel`, `ApiKernel`); a front controller must be adapted to use each one.
- **Debug**: `APP_DEBUG=0` in `.env` or `APP_DEBUG=1 php bin/console command_name`; becomes `kernel.debug`. Cache lives in `var/cache/<env>/`.

```php
final class Kernel extends BaseKernel
{
    use MicroKernelTrait;

    protected function build(ContainerBuilder $container): void
    {
        $container->addCompilerPass(new ReportGeneratorPass());
    }
}
```

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| `configureContainer()`, `configureRoutes()`, `getConfigDir()`, `getBundlesPath()` added to `MicroKernelTrait` | `registerContainerConfiguration()` can no longer return a `ContainerBuilder` (6.0) | `getAnnotatedClassesToCompile()`, `setAnnotatedClassCache()` deprecated (7.1); `__sleep`/`__wakeup` on kernels deprecated (7.4) | those removed; `__(un)serialize()`; `getShareDir()` on `KernelInterface` |

## Bundles

A bundle is software reusable as a stand-alone component, shared privately across company projects or publicly.

- **Use**: a bundle (in a private repository if needed) to reuse a feature across several projects.
- **Do not**: create bundles to organise your own application logic; use namespaces under `App\`.
- **Base class**: `AbstractBundle` (6.1+) is recommended; when extending `Bundle`, override `getPath()`.
- **Naming**: StudlyCaps, vendor prefix, `Bundle` suffix, no more than two words (`AcmeBlogBundle`); alias `acme_blog`.
- **Services**: prefix IDs with the alias; define all services explicitly, without autowiring or autoconfiguration, so application compilation carries no overhead. Internal services private; hidden ones prefixed with `.`; alias public services from interfaces.
- **Configuration**: simple settings as parameters prefixed with the alias (`acme_blog.author.email`); consider semantic bundle configuration for robustness.
- **Pitfalls**:
  - The bundle directory is read-only; write temporary files to the host application's `cache/` or `log/`.
  - Do not embed third-party PHP libraries or provide a main layout.
  - XML configuration is no longer supported in 8.0.

| 5.4 | 6.4 | 7.x | 8.x |
| --- | --- | --- | --- |
| `Bundle` | `AbstractBundle` (6.1); `BundleInterface` no longer extends `ContainerAwareInterface` (6.4) | fluent PHP format for semantic configuration deprecated (7.4) | fluent format removed; `Extension::addAnnotatedClassesToCompile()`, XSD methods removed |

## Review Checklist

- [ ] No new XML or config builder code on 7.4+.
- [ ] No production values in committed `.env`; sensitive values in the vault.
- [ ] `app.` prefix on application parameters; constants for rarely changing values.
- [ ] Web profiler not enabled in production.
- [ ] Bundle only when code is reused across projects.
