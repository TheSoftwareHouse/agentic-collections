## Primary keys

| Key | Use when | Cost |
| :-- | :-- | :-- |
| `bigint GENERATED ALWAYS AS IDENTITY` | the default for internal tables | ids are guessable and reveal volume when exposed |
| `uuid` with `uuidv7()` (18+), or UUIDv7 generated by the application | ids are created outside the database, exposed publicly, or merged across databases | 16 bytes against 8; time-ordered, so inserts stay at the right edge of the index |
| `uuid` with `gen_random_uuid()` (v4) | an existing schema already uses it | random values scatter inserts across the whole index: more page splits and cache misses on large tables |

- **`bigint`, not `integer`.** Running out of `integer` (2,147,483,647) forces the
  hardest migration there is. The extra 4 bytes are cheap.
- **`IDENTITY`, not `serial`.** `serial` creates a sequence with looser ownership and
  permission rules; identity columns are the SQL-standard replacement. `ALWAYS`
  rejects explicit values unless `OVERRIDING SYSTEM VALUE` is used, which catches
  code that invents ids.
- **On 17 and earlier, UUIDv7 comes from the application** (most UUID libraries
  generate v7) or an extension. Do not mix v4 and v7 in one key column.
- **Natural keys** (an email, a tax number) change and are reused. Keep them as
  `UNIQUE` columns beside a surrogate key, except for genuinely immutable codes such
  as ISO country codes in a lookup table.

## Text

- **`text` by default.** `varchar(n)` stores and performs the same; the only
  difference is the length check, and changing `n` later is a migration. When a
  maximum length is a real rule, prefer `text` with `CHECK (char_length(c) <= n)`,
  which is easier to change, or keep `varchar(n)` if the schema already uses it.
- **`char(n)` never.** It pads with spaces.
- **Case-insensitive values** (emails, usernames): a unique index on `lower(col)`,
  or the `citext` extension type. Pick one per schema.
- **Empty strings.** Decide whether `''` is a valid value; if not,
  `CHECK (c <> '')`. `NOT NULL` alone lets `''` through.

## Numbers and money

| Value | Type |
| :-- | :-- |
| counts, quantities, ids | `integer` or `bigint` |
| money | `numeric(p, s)` with the currency's scale, or `bigint` minor units (cents); currency code in its own column |
| exact decimals (rates, measurements with defined precision) | `numeric(p, s)` |
| scientific or approximate values | `double precision` |
| percentages | `numeric(5, 2)` or a `numeric` fraction; say which |

`real` and `double precision` cannot represent 0.10 exactly; sums drift by fractions
of a cent. The `money` type depends on the server's `lc_monetary` setting and carries
no currency. Neither belongs anywhere near an amount someone is billed.

## Time

| Value | Type |
| :-- | :-- |
| a moment: created, paid, expires | `timestamptz` |
| a calendar date with no time: birthday, invoice date | `date` |
| a wall-clock time with no zone: opening hour | `time` |
| a local date-time tied to a place: an event in Warsaw at 19:00 | `timestamp` **plus** a column with the IANA zone (`Europe/Warsaw`) |
| a duration | `interval` |
| a period | `tstzrange` or `daterange` |

`timestamptz` stores an absolute instant and converts on display using the session's
`TimeZone`. `timestamp` stores digits with no zone; two servers or drivers with
different defaults read different instants from it. Keep the database session in UTC
and convert at the edges.

## Booleans and status values

- `boolean NOT NULL DEFAULT false` for a true two-state flag. A nullable boolean has
  three states; make the third a deliberate one or forbid it.
- Several flags that are really one lifecycle (`is_paid`, `is_shipped`,
  `is_cancelled`) are one status column.
- A status with a fixed set of values:

| Option | Choose when |
| :-- | :-- |
| `text` with `CHECK (status IN (...))` | the default: easy to extend with a constraint swap |
| a lookup table with a foreign key | values carry data (labels, ordering, flags) or are managed by users |
| `CREATE TYPE ... AS ENUM` | the set is stable and ordering by declaration matters; values can be added and renamed, but not removed or reordered without a type swap |

## jsonb

`jsonb` (never `json`, which stores text and re-parses it) fits data whose shape the
schema does not own: a payload from a webhook, provider-specific settings, a
document stored and returned whole.

It does not fit attributes that are filtered on, joined, constrained, aggregated or
present on every row. Those are columns: they get types, `NOT NULL`, foreign keys and
statistics, and the planner can estimate them. A frequent pattern is a few real
columns extracted from the document, plus the document itself for the rest.

When a `jsonb` field is queried, a GIN index serves containment (`@>`); a B-tree
expression index serves one key (`(payload->>'orderId')`). A `CHECK` with
`jsonb_typeof` or a JSON-schema check in the application keeps its shape honest.

## Arrays

An array column fits a small, bounded list of scalar values owned by the row and read
with it (tags, a few phone numbers). It does not fit references to other rows
(no foreign keys on elements), lists that grow without bound, or elements that are
queried individually across rows: those are a child table.

## Other types worth knowing

| Type | For |
| :-- | :-- |
| `inet`, `cidr` | IP addresses and networks, with containment operators |
| `tstzrange`, `daterange` | periods; with an exclusion constraint, non-overlapping bookings |
| `bytea` | small binary values; large files belong in object storage with the key in the table |
| generated columns | values derived from other columns of the same row. On 18 the default is `VIRTUAL`, computed on read, which cannot be indexed and cannot call user-defined functions; write `STORED` explicitly when the column is indexed, part of a unique or primary key, or uses a user-defined function or type |
| domains | a reusable type with a check (`CREATE DOMAIN email AS citext CHECK (...)`); adding a column of a constrained domain rewrites the table |
